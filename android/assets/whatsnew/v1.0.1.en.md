agycodroid 1.0.1: a fix release. On some phones, 1.0 installed fine but the gateway wouldn't start and bash and curl in the terminal failed, because the bundled toolchain was still packaged for the old package name. This release switches the toolchain, update checks, notices, and components over to agycodroid's own, and fixes the issues found in the pre-release check.

## Upgrading from 1.0

- **Update the toolchain first, then the app**: update the toolchain to `devkit-2026.11.19` in the app, then update to 1.0.1 — otherwise the first launch re-downloads about 655 MB.
- **About 655 MB on first launch**: the toolchain installed by 1.0 can't be used by 1.0.1, so the first launch downloads it again; a failed download retries instead of failing silently.
- **Keep about 1 GiB free**: the download and unpack need about 1 GiB of free space.
- **In-app updates only accept packages signed with the new release certificate**: the update check verifies the signature, and a package that doesn't match won't install.

## What was fixed

- **Gateway and toolchain**: the new toolchain is packaged for `cc.agyroid`, so the gateway starts and bash and curl work in the terminal; "toolchain ready" is now a real probe (it actually runs bash and curl) instead of just checking a marker file; a failed first-time setup is recorded and notified, and the status clears once it recovers.
- **Updates and repair**: in-app updates only accept the new release certificate; "Repair" is no longer a dead end for 1.0 users — when the old manifest can't be fetched or its signature doesn't match, it falls back to the manifest bundled in the APK; download failures retry by cause (short backoff for network errors, no throttling when out of space), with a "Retry now" button when it fails, and the downloaded archive isn't deleted before it's verified.
- **Chat and usage**: switching permission modes actually takes effect, and invalid values are rejected; the usage page no longer opens blank; the first message is no longer lost when agy doesn't send an init signal; "Usage this session" now shows up.
- **Sign-in**: signing out with an API Key really clears the key instead of reporting success while keeping it; signing out only signs out the provider you picked; an expired sign-in now looks different from never having signed in (it asks you to sign in again); cancelling sign-in no longer leaves the old signed-in state showing; the welcome page no longer says DeepSeek, GLM, Qwen, or Kimi keys work; /login in chat no longer shows broken links and polls while sign-in is in progress.
- **Components**: when the index isn't published yet, the page no longer opens to an error — it says so plainly; an unreachable community source no longer paints red errors; after a toolchain update, the extensions page offers to reinstall all components at once.
- **Files and terminal**: file names now support emoji and extension-B CJK characters; the terminal checks the shell before each start and falls back with a message when it isn't usable; a file too large to preview can be opened with another app.
- **Branding and sources**: the UI, notices, components, and update checks all go through GitHub only; leftover QQ group, Discord, and upstream mirror references are gone.

## Notes

- This release needs the new toolchain `devkit-2026.11.19` (published with 1.0.1); the old toolchain is no longer accepted.
- Test suite: 1,643 gateway tests pass, 3 fail (all environment issues); Java tests all pass.
