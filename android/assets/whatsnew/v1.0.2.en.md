agycodroid 1.0.2: a fix release. On some phones, 1.0.1 got stuck on first launch at "first-time setup", re-running the same setup over and over without ever getting in. This release stops a failed first-time setup from blocking entry, and a stuck device can recover by updating to 1.0.2 and going straight to the update install.

## Upgrading from 1.0.1

- **Update the app first, then the toolchain**: on a device stuck at first-time setup, update the APK to 1.0.2 first; on launch, when a new toolchain is available, it skips the re-run that was bound to fail and goes straight to the update install — no need to clear data and reinstall by hand.
- **The first launch may still download a new toolchain**: the toolchain installed by 1.0.1 is no longer accepted by 1.0.2, so the first launch downloads the new one (about 655 MB); a failed download retries instead of failing silently.
- **Keep about 1 GiB free**: the download and unpack need about 1 GiB of free space.

## What was fixed

- **First-time setup no longer blocks entry**: Python pre-compilation now runs serially, and a failure only logs a warning and carries on instead of failing the whole setup; a failed non-essential step no longer blocks entry either, while the ledger and the UI still record a warning line for later troubleshooting.
- **Stuck devices can recover**: on launch, when the on-disk setup is bound to fail again but a new toolchain is already available, the app no longer re-runs the old setup — it goes straight to the update install. The update install only re-runs the modules that haven't finished; finished ones are skipped, and a failed module no longer triggers a full reinstall and re-download.
- **Retries resume where they stopped**: a retry skips modules that already finished and only re-runs the ones that didn't; a single setup run waits at most 10 minutes before stopping and recording it, instead of waiting forever.
- **Failures can be traced**: when first-time setup fails, the failed step name, return code, and log path are recorded in the ledger; a diagnostics bundle reads the failure marker, states the cause, and attaches the tail of the log, so there's no more guessing.
- **Connectivity probing**: the connectivity probe no longer sits on the main thread; the app only falls back to the backup address when the connection genuinely fails, and no longer falls back by mistake when the probe hasn't run yet.
- **Download failures are handled by cause**: download failures are classified into network, checksum, out-of-space, and read errors and retried accordingly — a checksum failure no longer backs off as if it were a network problem, and running out of space no longer throttles pointlessly.

## Notes

- This release needs the new toolchain `devkit-2026.11.20` (published with 1.0.2); the old toolchain is no longer accepted.
- Test suite: 1,645 gateway tests pass, 3 fail (all local-environment issues: the disk doesn't enforce permission bits, tar can't change file ownership, and unpack capping can't see free-space changes); Java tests all pass (326 checks); toolchain first-run tests 14/14.
